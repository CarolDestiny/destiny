# Destiny Replay 追踪格式 v1

状态：架构决策，尚未开始实现  
格式版本：1.0  
文件族：运行期追踪文件 `.dtrace` + 构建映射文件 `.dmap`

本文档是 [英文规范](TRACE_FORMAT_V1.md) 的等价中文版本。协议字段名、
事件名和文件魔数保留英文，以避免实现时产生二义性。

## 1. 架构决策

`core/replay` 只暴露一个小型采集接口并写入运行期事实。它不解析源代码、
不对地址进行符号化、不推断变量名，也不渲染面向用户的时间线。这些职责属于
离线还原器。

双方之间稳定的接缝由一对带版本的文件构成：

- `<session>.dtrace`：运行期写入的、仅追加且可容忍崩溃的二进制事件流。
- `<build-id>.dmap`：在 `core/replay` 外部，根据精确匹配的链接映像、调试信息、
  编译数据库和源码快照生成的不可变二进制源码/构建映射。

两个文件通过精确的 `build_id` 绑定。没有映射文件时，追踪文件仍然有效，
但其中的源码位置保持未解析状态。同一构建生成的任意数量会话都可以复用同一
映射文件。

默认的根目录相对存储布局为：

```text
cache/replay/maps/<build-id>.dmap
cache/replay/sessions/<session-id>.dtrace
```

JSON 只允许作为可选的诊断导出格式，不能作为 v1 的存储协议。超大型工程可能
包含数百万个追踪点，因此两个权威文件都使用带索引的二进制容器。

## 2. 不可妥协的可行性约束

对象地址（或项目句柄）、函数指针和源代码三者加在一起，仍不足以还原变量级
事件。

这些信息最多只能识别事件所在的映像或函数，无法区分同一函数内的两次写入、
循环迭代、内联函数、被优化的变量、别名或并发调用。经过 ASLR、优化、内联、
跳板函数生成、相同代码折叠或链接时优化后，仅凭源码也无法可靠地映射运行期
地址。

因此，每个细粒度事件都必须携带下列源码点键之一，可靠性由高到低排列：

1. 由构建过程生成并通过插桩嵌入的 `site_id`；
2. 规范化为 `(image_instance_id, rva)` 的指令地址；
3. `(function_ref, event_ordinal)`，其中序号由插桩产生，并且在精确构建内稳定。

裸函数指针只适用于函数进入/退出事件。如果运行期无法提供上述三种键中的任何
一种，v1 必须把该事件标记为函数级事件，不得声称可以进行变量级还原。

同理，如果只有对象地址而没有明确的生命周期开始/结束观测，该地址就不能成为
稳定的变量身份，因为栈和堆地址都可能被复用。生命周期未知时，事件必须携带
不透明的观测 ID，还原器不得把多个独立观测合并成同一个变量。

精确还原还要求使用匹配的 PDB、DWARF、链接器信息或预生成的 `.dmap`。只有
源码检出目录时，只能作为能力降级的后备方案。

## 3. 保证与非目标

v1 保证：

- 精确的线程内事件顺序；
- 明确声明的跨线程排序语义；
- 稳定的调用、栈帧、对象生命周期、映像和源码点身份；
- 与构建和源码快照精确匹配；
- 明确表示缺失、已脱敏、不可用和丢失的数据；
- 文件尾被截断或进程崩溃时，恢复此前每一个完整数据块；
- 向前跳过未知的可选数据块和记录。

v1 本身不保证进程的确定性重新执行。实现确定性重新执行还需要采集并控制线程
调度、系统调用、I/O、时间、随机数、信号、设备以及其他所有非确定性输入。
模块名称是 `replay`，但 v1 产物明确是一份用于还原详细时间线的观测追踪。

## 4. 身份模型

裸地址只是一次观测结果，绝不是持久身份。

| 实体 | 持久身份 |
| --- | --- |
| 项目 | 分配给仓库且永不变化的 128 位 `project_id` |
| 源码快照 | VCS 修订号 + 所有参与构建文件的摘要 |
| 构建 | 根据规范化清单和映像哈希计算的 SHA-256 `build_id` |
| 已加载映像 | 会话内 `image_instance_id` + 精确映像构建 ID |
| 代码位置 | `image_instance_id` + RVA，或精确构建内的 `site_id` |
| 线程 | 会话内单调分配的 `thread_id` |
| 函数调用 | 会话唯一的 `call_id` + 可选 `parent_call_id` |
| 变量声明 | `.dmap` 中精确构建内的 `variable_id` |
| 运行期对象 | 单次生命周期内会话唯一的 `object_id` |
| 变量实例 | `variable_id` + `call_id` + `object_id` |
| 大值 | 会话内 `blob_id` |

某个生命周期结束后，其地址可以被复用，但旧的 `object_id` 永远不能随地址一起
复用。除非子对象具有独立生命周期，否则使用
`(object_id, byte_offset, subobject_site_id)` 引用子对象，而不为其分配新身份。

已知映像内的函数指针和数据指针被规范化为该映像的 RVA。条件允许时，堆/栈
指针被规范化为 `(object_id, byte_offset)`。其他地址按照会话地址策略记录：
`none`、`hashed`，或者明确选择启用的 `raw`。

C++ 成员指针的表示依赖 ABI，并且可能不止包含一个地址。v1 不接受其原始字节
作为函数身份。插桩层必须把它解析为可调用入口或追踪点，否则将其标记为不透明。

## 5. 通用二进制容器

所有定宽整数都使用小端序。载荷中的 ID、数量和增量使用无符号 LEB128，
有符号增量使用有符号 LEB128。字符串使用 UTF-8 并通过字符串表引用。源码路径
统一使用 `/`，相对于已声明的源码根目录，并携带内容摘要。

### 5.1 文件头（64 字节）

| 偏移 | 大小 | 字段 | 规则 |
| ---: | ---: | --- | --- |
| 0 | 8 | `magic` | 追踪文件为 ASCII `DREPLAYT`，映射文件为 `DREPLAYM` |
| 8 | 2 | `major` | `1` |
| 10 | 2 | `minor` | `0` |
| 12 | 2 | `header_bytes` | `64` |
| 14 | 1 | `byte_order` | `1` 表示小端序 |
| 15 | 1 | `address_bytes` | 产出该文件的构建使用 `4` 或 `8` 字节地址 |
| 16 | 8 | `required_features` | 读取器必须理解每一个已置位特性 |
| 24 | 16 | `file_id` | 随机 UUID；对 `.dtrace` 而言就是会话 ID |
| 40 | 8 | `created_unix_ns` | UTC Unix 纳秒时间戳 |
| 48 | 8 | `first_chunk_offset` | v1 固定为 `64` |
| 56 | 8 | 保留字段 | 全部为零；读取器忽略 |

`byte_order` 描述的是容器格式，不是被追踪程序的本机对象表示。v1 写入器只能
生成小端序容器。

### 5.2 数据块头（40 字节）

| 偏移 | 大小 | 字段 | 规则 |
| ---: | ---: | --- | --- |
| 0 | 4 | `chunk_magic` | ASCII `CHNK` |
| 4 | 2 | `chunk_type` | 文件类型专属的数据块类型 |
| 6 | 2 | `chunk_flags` | 压缩或可选标志 |
| 8 | 4 | `header_bytes` | 至少为 `40` |
| 12 | 4 | 保留字段 | 全部为零 |
| 16 | 8 | `payload_bytes` | 存储态载荷长度 |
| 24 | 8 | `chunk_sequence` | 从 0 开始并严格递增 |
| 32 | 4 | `header_crc32c` | 两个 CRC 字段归零后计算的数据块头 CRC |
| 36 | 4 | `payload_crc32c` | 存储态载荷 CRC |

数据块只能追加。写入器绝不回头修复已经写入的数据块。读取器接受所有完整且
校验有效的数据块，并丢弃不完整的最后一个数据块。最终索引和结束标记可以提升
随机访问能力，但进程崩溃后允许缺失。

压缩以单个数据块为单位，绝不跨越数据块边界。核心元数据和丢失记录不压缩。
v1 将数据块标志位 0 保留给 Zstandard 载荷；只有同时声明必需特性位 0
（`zstd_chunks`）时，写入器才能使用它。v1 的其他必需特性位和数据块标志位
全部为零。

### 5.3 通用线格式值

下列嵌套值各自只有一种规范编码：

| 值 | 编码 |
| --- | --- |
| `CodeRef` | `image_instance_id: ULEB128`，随后是 `rva: ULEB128` |
| `FunctionRef` | 指向可调用入口的一个 `CodeRef` |
| `SiteRef` | u8 标签：1 = `site_id`，2 = `CodeRef`，3 = `FunctionRef` + `event_ordinal` |
| `ObjectRef` | `object_id: ULEB128`、`byte_offset: ULEB128`、`subobject_site_id: ULEB128` |
| `VariableRef` | u8 标签：0 = 未解析，1 = 精确构建内的 `variable_id` |
| `StringRef` | 当前表内的 `string_id: ULEB128`；零表示不存在 |
| `BlobRef` | 会话内的 `blob_id: ULEB128` |
| `Bytes` | ULEB128 字节长度，随后紧跟长度完全一致的字节 |

`event_ordinal`、所有 ID 和 RVA 都是无符号 LEB128。值为零的
`subobject_site_id` 表示没有静态识别出的子对象。运行期采集可以使用未解析的
`VariableRef`；只有精确 `SiteRef` 能唯一映射时，还原器才可以解析它。模块绝不
伪造变量 ID。

## 6. 运行期追踪文件 `.dtrace`

### 6.1 数据块类型

| ID | 名称 | 数量 | 用途 |
| ---: | --- | --- | --- |
| 1 | `SESSION` | 恰好一个且必须位于首位 | 项目/构建绑定、策略和时钟 |
| 2 | `STRING_TABLE` | 零个或多个增量块 | 线程名等仅存在于运行期的字符串 |
| 3 | `BLOB_BLOCK` | 零个或多个 | 以 `blob_id` 为键的大值载荷 |
| 4 | `EVENT_BLOCK` | 一个或多个 | 带长度边界的运行期事件 |
| 5 | `LOSS_BLOCK` | 零个或多个 | 显式记录丢失或损坏的事件区间 |
| 6 | `CHECKPOINT` | 零个或多个 | 最后持久化的序列和字典状态 |
| 7 | `INDEX` | 零个或一个 | 按线程、时间和序列组织的可选偏移索引 |
| 8 | `END` | 零个或一个且必须位于末尾 | 正常关闭计数以及 `END` 前全部字节的 SHA-256 |

`SESSION` 包含：

- `project_id`、根可执行文件的 `build_id`，以及最初已知的每个映像构建 ID；
- 进程 ID、父进程 ID、可执行文件名、目标三元组、ABI 标签和指针宽度；
- 实时时钟（wall clock）起始时间，以及单调时钟的类型、原点和频率；
- 排序模式：`thread_causal` 或 `global_total`；
- 值策略和地址策略；
- 记录器的 schema/构建版本以及已启用的可选特性。

绝对源码根路径和可执行文件路径只是可选诊断信息，不得用作身份。

### 6.2 事件块

每个事件块只属于一个线程，其固定逻辑前缀为：

| 字段 | 编码 | 含义 |
| --- | --- | --- |
| `thread_id` | u32 | 所属线程 |
| `block_flags` | u32 | 排序和压缩细节 |
| `first_thread_seq` | u64 | 第一条记录的线程序列号 |
| `first_global_seq` | u64 | 非 `global_total` 模式下为零 |
| `base_ticks` | u64 | 单调时间戳基值 |
| `event_count` | u32 | 载荷中的完整记录数 |
| `event_schema_minor` | u16 | 事件载荷 schema 的小版本 |
| 保留字段 | u16 | 零 |

每条记录使用以下封装结构：

```text
record_bytes: ULEB128
kind:         ULEB128
flags:        ULEB128
tick_delta:   ULEB128
seq_delta:    ULEB128
payload:      事件类型专属字节
```

在 `global_total` 模式下，`global_seq_delta` 紧跟在 `seq_delta` 后面。
记录长度使读取器可以跳过未知的可选事件。事件块的刷盘顺序不表达时间线语义；
序列号和时间戳才表达该语义。

### 6.3 核心事件

| ID | 事件 | 按线格式顺序排列的必需逻辑字段 |
| ---: | --- | --- |
| 1 | `ImageLoad` | 映像实例、映像构建 ID、规范化加载基址令牌、大小 |
| 2 | `ImageUnload` | 映像实例 |
| 3 | `ThreadStart` | 线程、父线程、可选名称 |
| 4 | `ThreadEnd` | 线程、结果 |
| 10 | `FunctionEnter` | 调用 ID、父调用 ID、函数代码引用、调用点引用 |
| 11 | `FunctionExit` | 调用 ID、返回点引用、可选返回值 |
| 12 | `FunctionUnwind` | 调用 ID、抛出/取消原因、追踪点引用 |
| 20 | `VariableLifetimeBegin` | 对象引用、变量引用、栈帧调用 ID、追踪点、存储类别、大小 |
| 21 | `VariableRead` | 对象引用、变量引用、栈帧调用 ID、追踪点、值引用 |
| 22 | `VariableWrite` | 对象引用、变量引用、栈帧调用 ID、追踪点、写入前/后值引用 |
| 23 | `VariableLifetimeEnd` | 对象引用、变量引用、栈帧调用 ID、追踪点、原因 |
| 30 | `Allocation` | 对象 ID、分配器类别、大小、对齐、追踪点 |
| 31 | `Free` | 对象 ID、追踪点、原因 |
| 40 | `Synchronization` | 操作、同步对象 ID、获取/释放令牌 |
| 50 | `Marker` | 类别 ID、追踪点、可选值/字符串引用 |

必需字段从左向右编码。除非上述通用线格式值另有规定，事件载荷内的 ID、大小、
枚举和标志都使用 ULEB128。记录标志声明存在可选字段时，可选字段位图必须是
载荷的第一个值。ID 0、5-9、13-19、24-29、32-39 和 41-49 均为保留值，
写入器不得使用。

代码引用是 `(image_instance_id, rva)`。追踪点引用带有标签，可以是 `site_id`、
代码引用，或者 `(function_ref, event_ordinal)`。事件载荷不得直接转储本机 C++
结构体；结构体填充、枚举大小和 ABI 都不能成为文件格式。

异常退出时不发送 `FunctionExit`，而发送 `FunctionUnwind`。除非 `LOSS_BLOCK`
或非正常进程终止明确表明区间不完整，否则每个已进入调用必须恰好由这两个事件
之一结束。

### 6.4 排序模式

默认模式为 `thread_causal`。每个线程通过 `thread_seq` 形成全序；
`Synchronization` 事件提供跨线程的先行发生边。不存在因果边的事件保持并发，
还原器不得因为时间戳接近而虚构全序。

`global_total` 为每个事件增加一个会话范围内单调递增的 `global_seq`，以额外的
同步成本记录“记录器观测顺序”。即便如此，它也不能证明数据竞争中的语言级
内存顺序。

### 6.5 值

一个值引用包含 `type_id`、采集状态以及下列一种编码：

| 编码 | 含义 |
| --- | --- |
| `canonical_scalar` | 使用容器字节序的定宽整数、浮点数或布尔字节 |
| `utf8` | 带长度前缀的 UTF-8 文本 |
| `object_bytes` | 目标平台本机字节；只在 ABI 和构建映射精确匹配时有效 |
| `inline_bytes` | 最多 32 个未解释字节 |
| `blob_ref` | 存储在 `BLOB_BLOCK` 中的大块字节 |
| `sha256` | 按策略只用摘要表示的值 |
| `redacted` | 策略隐去该值，并记录原因码 |
| `unavailable` | 被优化掉、不可读、发生撕裂或不受支持 |
| `none` | 该事件不要求携带值 |

浮点数使用其位模式，写入器不进行十进制转换。非平凡 C++ 对象必须在 `.dmap`
中提供显式序列化器描述；盲目复制对象存储绝不能被呈现为语义值。会话必须声明
是否采集写入前值、写入后值、读取值和指针地址。

### 6.6 丢失与失败

丢失是数据，不是一条日志消息。`LOSS_BLOCK` 记录：

- 受影响的线程，或所有线程；
- 已知时，首个缺失的线程内/全局序列号和缺失数量；
- 时间区间；
- 原因：`buffer_full`、`allocation_failure`、`io_failure`、`unsupported`、
  `corrupt_block`、`process_crash` 或扩展值；
- 最后一个已持久化检查点。

还原器把所有受影响的栈帧和对象标记为不完整，绝不在丢失区间两端拼接值并假装
连续性已经得到证明。

如果文件没有有效的 `END` 数据块，读取器还必须在最后一个持久化检查点之后
合成一个非正常终止缺口。发生硬崩溃的进程不应被期望自行追加
`process_crash` 丢失记录。

## 7. 构建映射文件 `.dmap`

映射文件针对一个精确构建生成，使用相同的文件和数据块框架，并包含以下类型：

| ID | 名称 | 内容 |
| ---: | --- | --- |
| 1 | `MANIFEST` | 项目、构建、源码、编译器、链接器和 ABI 身份 |
| 2 | `STRING_TABLE` | 去重后的 UTF-8 字符串 |
| 3 | `IMAGE_TABLE` | 映像 ID、精确哈希、首选基址和节信息 |
| 4 | `FILE_TABLE` | 根目录相对路径和 SHA-256 内容哈希 |
| 5 | `TYPE_TABLE` | 类型 ID、名称、大小/对齐、编码/序列化器 |
| 6 | `FUNCTION_TABLE` | 函数 ID、名称、映像/RVA 范围和源码跨度 |
| 7 | `SITE_TABLE` | 追踪点 ID、事件类型、函数 ID 和源码位置 |
| 8 | `VARIABLE_TABLE` | 声明 ID、作用域、类型、存储类别和位置 |
| 9 | `INLINE_TABLE` | 内联调用链和判别号 |
| 10 | `INDEX` | 按 ID、RVA 范围、文件、函数和追踪点查找 |
| 11 | `END` | 表计数以及 `END` 前全部字节的 SHA-256 |

表项使用带长度边界的记录。ID 是构建映射内局部有效的稠密无符号整数。同一种
表可以拆分到多个同类型数据块中，索引负责解析其字节范围。

### 7.1 清单必须包含的证据

清单至少包含：

- `project_id` 和 SHA-256 `build_id`；
- 仓库修订号和脏工作树摘要；
- 目标三元组、体系结构、字节序、ABI、编译器 ID/版本；
- 完整编译选项和预处理定义摘要；
- 链接器身份/选项、优化、LTO 和相同代码折叠状态；
- 可执行文件/库映像以及 PDB、DWARF、链接器产物的精确哈希；
- 编译数据库摘要；
- 每个参与构建的源码文件的根目录相对路径和内容哈希；
- 映射生成器名称/版本和生成时间戳。

仅有 Git 提交号并不足够，因为生成文件、脏工作树改动、工具链、编译参数和
链接顺序都可能改变地址和优化结果。

为避免递归定义，`build_id` 按以下内容计算 SHA-256：先输入移除 `build_id`
字段后的规范化清单，再按顺序输入精确的映像哈希和调试产物哈希。清单同时记录
规范化算法及其版本。

### 7.2 追踪点与映射质量

每条追踪点记录包含：

- `site_id`、所属 `function_id` 和预期事件类型；
- 文件 ID、行、UTF-8 列、词法作用域和判别号；
- 零个或多个指令 RVA 范围；
- 内联链 ID；
- 映射质量：`exact`、`range`、`ambiguous` 或 `unavailable`；
- 映射存在歧义时的可选候选 ID。

优化后的代码可能合并、移动或删除操作。映射文件必须记录这一事实。离线还原器
可以显示候选项和置信度，但绝不能静默选择一个源码变量或源码行。

## 8. 还原流水线

```text
精确可执行文件 + 调试产物 + 编译数据库 + 源码快照
                         |
                         v
                  映射生成器 -> .dmap
                                      \
已插桩进程 -> core/replay -> .dtrace -> 离线还原器 -> 派生视图
```

还原器按以下顺序执行关卡：

1. 验证文件头、特性位、数据块 CRC 和序列连续性；
2. 源码符号化前要求项目、构建和映像 ID 精确匹配；
3. 验证源码内容哈希，而不只是文件路径；
4. 通过映射索引解析代码引用和追踪点引用；
5. 配对调用和变量生命周期，绝不跨越丢失区间；
6. 构建线程内顺序和已声明的跨线程因果边；
7. 只有类型、ABI、序列化器和采集策略都允许时才解码值；
8. 显式标记每一个未解析或有歧义的结果。

派生时间线、JSON、火焰图和源码标注都是可丢弃视图，不得回写权威追踪文件。

## 9. 兼容性规则

- 只有框架或语义不兼容时才增加主版本号。
- 小版本可以增加可选数据块、事件、字段、编码或标志。
- 未知且带长度边界的可选记录可以跳过。
- 出现未知的 `required_features` 位时必须硬失败。
- 已存在的数值 ID 和语义永远不能复用。
- 写入器应生成能够表达全部已启用特性的最旧小版本。
- 读取器进行容器级复制时必须保留未知字节。
- v1 之后，`.dtrace` 和 `.dmap` 可以独立演进版本；各自清单声明可接受的对端
  版本范围。

## 10. 安全与隐私

极端细粒度追踪可能包含凭据、个人数据、专有源码结构和可被利用的地址。完整值
采集和裸地址采集必须显式选择启用，不能作为默认策略。每个追踪文件都必须记录
自身策略，防止消费者把“已脱敏”误认为“空值”。

v1 提供完整性校验，但不提供加密。存储加密应位于容器下层，或者作为未来的
必需特性加入。访问控制和保留期限属于部署职责。除非显式启用，否则排除诊断用
绝对路径、命令行和环境变量。

## 11. 职责接缝

`core/replay` 负责：

- 分配会话、线程、调用和对象 ID；
- 接受规范化的运行期事件；
- 管理线程内缓冲、数据块框架、校验和、检查点和显式丢失记账；
- 保证 `.dtrace` 符合规范。

插桩层负责生成有效的追踪点、函数、对象和值观测。插桩可以基于编译器、宏、
包装器或平台机制，但这些机制都不作为 replay 模块接口的一部分暴露。

离线工具链负责：

- 生成精确构建映射并保证 `.dmap` 符合规范；
- 调试信息/源码解析、符号化、歧义报告、还原、查询和可视化。

这条接缝把源码解析器、编译器专属调试信息读取器和 UI 模型留在运行期模块之外。
文件协议是双方共享的接口。

## 12. 接受实现前的符合性关卡

实现只有通过以下测试后才符合 v1：

- 文件头、数据块和核心事件记录的逐字节黄金样本；
- 最后一个数据块在每个字节处截断后的读取恢复；
- CRC 失败隔离和显式丢失报告；
- ASLR 规范化以及映像反复加载/卸载时的身份处理；
- 地址复用但绝不复用 `object_id`；
- 递归、异常、内联、重载和存在歧义的优化追踪点；
- 并发下线程内排序和因果/全局排序行为；
- 源码、构建或哈希不匹配时拒绝处理；
- 已脱敏、不可用、仅哈希、内联和大块值；
- 跳过未知可选记录，并拒绝未知必需特性；
- 使用有界的读取器和写入器内存处理数 GB 追踪文件。

这些关卡验证的是文件接缝。内部缓冲和插桩实现可以改变，而不影响消费者。
