# Destiny Core Replay 架构计划

状态：架构设计收口稿，尚未开始 Replay 源码实现。

本文档只定义 `source/core/replay` 的职责、契约、数据模型、生命周期、文件分工和实施顺序。它不是已经提交的实现，也不是要求现在立即冻结所有字节偏移的最终二进制规范。除非明确标记为“待冻结”，本文中的“必须”表示实现不可违背的架构约束。

## 0. 文档定位

`core/replay` 是 Destiny 内部开发模块，由 Destiny 各模块的开发者调用，不面向 Destiny 库的最终用户。它记录运行期事实，离线工具再依据精确的构建映射和源代码还原函数、变量、控制流和对象生命周期。

本文使用以下文件概念：

```text
<session>.dtrace       运行期追踪文件
<build-id>.dmap        构建期源码/类型映射文件，可由外部工具生成
```

`.dtrace` 是运行过程中产生的权威事实；`.dmap` 是把运行期指针和描述符映射到源代码的静态字典。没有 `.dmap` 时，`.dtrace` 仍然有效，但只能显示未解析的地址和描述符。

## 1. 目标和非目标

### 1.1 目标

- 在不阻塞业务线程的前提下，追踪被模块开发者明确选中的函数调用、控制流、对象生命周期和变量快照。
- 让高频事件可以丢失，并让离线解析器通过全局事件 ID 缺口发现丢失数量。
- 让对象构造、析构和地址复用可以被解析，支持在完整记录区间内判断泄漏。
- 让 `if`、循环、`switch`、短路表达式等运行时控制流可以由源代码映射还原。
- 保留 Destiny 的 `TypeCodeBase` / `TypeCode` 项目协议，同时允许 Replay 内部描述符使用 Replay-local identity。
- 把源代码、调试信息、编译器和链接器依赖隔离在外部格式化工具，不把它们放入 Replay 热路径。
- 在 Debug/Release 构建之间提供可验证的零开销关闭路径。

### 1.2 非目标

- v1 不承诺确定性重新执行。真正的重新执行还需要调度、系统调用、I/O、时间、随机数和设备输入的控制。
- Replay 不自动解析任意 C++ 表达式、任意对象布局或任意函数指针 ABI。
- Replay 不自动记录 `destinyNumeric` 等基础类型的每一次普通运算。
- Replay 不保证事件永不丢失，也不因为磁盘、CPU 或内存故障阻塞业务线程。
- Replay 不在运行时读取源代码、解析 PDB/DWARF、生成函数名或渲染用户时间线。
- Replay 不支持运行期间动态切换采集开关。

## 2. 已冻结的架构决定

以下决定已经由设计讨论确认，后续实现不得悄悄改回旧草稿中的替代方案。

1. **采集开关是编译期决定的。** Release 构建中采集宏必须在预处理阶段展开为空，并且不求值参数。Debug 构建可以编译开启或关闭 Replay，但运行期间没有原子开关、配置文件开关或动态启停。
2. **MPSC 槽位只存 `ReplayInfoBlock*`。** 信息块自身不是原子对象；生产者完成快照后通过队列发布指针，消费者取得指针后序列化并归还块。
3. **不采用线程本地页。** Replay 使用固定容量块池和有界 MPSC。不能把线程本地页作为降低原子成本的前提，也不能在热路径使用普通 `new/delete`。
4. **所有运行时事件共享一个全局原子事件 ID。** `GlobalEventId` 由 `uint64_t` 全局计数器取得，按取得 ID 的线性化顺序重构事件。池耗尽、队列满或其他采集失败仍然消耗 ID，形成可检测缺口。
5. **静态描述表不占运行时事件 ID。** 模块 `onload()` 注册编译期确定布局的描述符，Replay 封存元数据后才允许产生运行时事件。
6. **TypeCode 是可选的语义身份，不是所有 Replay 描述符的强制字段。** 需要进入 Destiny 全局协议的类型附带 TypeCode；只服务于 Replay 的控制点、变量或指针描述可以使用 Replay-local identity。
7. **动态对象不使用额外协议。** 所有对象统一由构造记录和析构记录表示。完整、正常收尾且没有相关 ID 缺口时，构造存在而析构缺失就是泄漏。
8. **控制流使用标准化控制点事件。** Replay 不理解 C++ 语法；插桩层提供控制点描述符、选中的控制流边和短路求值掩码。
9. **物理写入顺序不等于逻辑顺序。** MPSC 消费者不等待低 ID 事件，文件可以按到达顺序追加；离线解析器按 `GlobalEventId` 归并或排序。
10. **Replay 最先加载、最后卸载。** 模块卸载前必须停止产生新事件；Replay 排空队列、写结束信息并关闭文件后才释放自己的描述符和块池。
11. **Replay 内部和公开采集入口均为 `noexcept`。** 失败只能造成丢失、未解析或最终停止 Replay，不能让业务进程因为未捕获 C++ 异常崩溃。
12. **主运行期文件 v1 只有一个。** `.dmap` 是构建期映射字典，可以单独生成并复用。若未来把运行期元数据拆成第二个 Destiny 文件，该文件必须拥有独立的文件 TypeCode。

## 3. 必须继承的 Destiny 契约

### 3.1 TypeCode

Replay 不替换 `TypeCodeBase` 和 `TypeCode`，也不重新定义一套项目级错误或文件身份。

- `TypeCode` 逻辑上仍是高 32 位 `category`、低 32 位 `value` 的 64 位编码。
- 模块注册类型时可以提供 `const TypeCodeBase&`；Replay 只在注册阶段读取并复制 `getTypeCode()` 和 `getProtectLen()`。
- Replay 热路径不能每条事件调用虚函数，也不能保存模块卸载后仍会悬空的 `TypeCodeBase*`。
- Replay 文件的文件级身份使用 Destiny 文件 TypeCode。Replay 内部的 `record_kind` 和描述符标签是结构性字段，不冒充 TypeCode。

### 3.2 无异常和生命周期

- 所有模块有 `onload()` / `unload()`；Replay 的生命周期由 core runtime 编排。
- Replay 不反向调用业务模块，不持有业务模块的所有权。
- 模块卸载前应停止引用其代码和静态描述符；Replay 已经复制的数值元数据必须可以在模块代码卸载后继续解析。

### 3.3 依赖方向

```text
define / TypeCode
        ↓
queueBoundMPSC、memory port、thread context port、文件 append port
        ↓
core/replay
        ↓
各业务模块的 Replay 插桩适配器
        ↓
外部 .dmap 生成器和离线还原器
```

`queueBoundMPSC` 位于 Replay 依赖层以下，自身不能调用 Replay，否则会形成循环依赖或递归追踪。Replay 不直接依赖业务模块的具体头文件。

## 4. 编译开关和采集接口

现有 `DESTINY_DEBUG` 的判断方向保持“未定义 `NDEBUG` 为 Debug，定义 `NDEBUG` 为 Release”，但注释和 CMake 传递方式需要在实现阶段统一。

建议使用三个层次的宏语义：

```text
DESTINY_BUILD_DEBUG      构建模式
DESTINY_REPLAY_ENABLE     Debug 构建是否编译采集路径
DESTINY_REPLAY_ACTIVE     最终是否生成采集代码
```

矩阵如下：

| 构建 | 采集宏 | `onload()` | 业务参数是否求值 |
| --- | --- | --- | --- |
| Release | 空操作 | 空操作/成功返回 | 否 |
| Debug + disabled | 空操作 | 空操作/成功返回 | 否 |
| Debug + enabled | 调用 Replay 入口 | 建立池、队列、元数据和 writer | 是 |

采集宏必须保证关闭分支不生成字符串构造、快照复制、ID 原子操作或对参数的副作用。CMake 应通过 target-scoped compile definitions 传播宏，不能只对 Replay 静态库私下定义而让业务翻译单元看到另一套状态。

## 5. 模块内部边界

Replay 的实现可以拆成以下私有区域，公开接口保持很小：

```text
replay/
  include/                 模块开发者可见的最小采集入口
  src/runtime/             onload、unload、状态机
  src/registry/            模块和静态描述符注册、seal
  src/producer/            执行上下文和生产者状态
  src/pool/                固定块池和所有权状态
  src/queue/               queueBoundMPSC 适配
  src/event/               事件规范化和快照复制
  src/writer/              文件追加、分帧、flush、checkpoint
  src/recovery/            启动恢复、尾部截断和缺口识别
  src/format_contract/     .dtrace/.dmap 契约常量和校验
  docs/                    架构、计划和协议文档
```

`registry`、`pool`、`queue` 和 `writer` 不应出现在业务模块的公共头文件中。业务模块只知道描述符引用、事件入口的契约和“失败不影响业务”的性能语义。

## 6. 身份模型

Replay 必须区分下列编号，禁止用“index”同时称呼它们：

| 名称 | 范围 | 作用 |
| --- | --- | --- |
| `TypeCode` | Destiny 项目级 | 可跨模块、可持久化的语义身份 |
| `ReplayDescriptorPointer` | 单次运行 | 事件查找静态函数、控制点、变量或类型描述 |
| `GlobalEventId` | 单次会话 | 所有运行时事件的逻辑顺序 |
| `ExecutionContextId` | 单次会话 | 线程或执行上下文实例 |
| `CallInstanceId` | 单次会话 | 一次函数进入的调用实例 |
| `ObjectInstance` | 解析器内部 | 地址复用后的对象生命周期实例 |
| `FormatKey` | 精确构建 | `.dmap` 中稳定查找源代码和布局的键 |

事件可以保存原始指针，但原始指针不是跨运行持久身份。格式化程序必须结合模块实例、构建 ID、加载基址或相对地址进行解析。

### 6.1 静态描述符

静态描述符数量和布局可在编译期确定，运行时只在 `onload()` 填入地址或模块实例信息。

`ModuleDescriptor` 至少描述模块实例、构建身份和加载范围。

`FunctionDescriptor` 至少描述函数描述符指针、函数入口或代码范围、所属模块、函数类别和格式化键。成员函数、模板实例、内联函数和代码折叠不得只依赖一个普通函数地址。

`ControlSiteDescriptor` 至少描述所属函数、控制流类型、边数量、操作数数量、描述符指针和格式化键。边表把运行时的 `selected_edge` 翻译成 true/false、循环继续/退出、case、break、continue 或 return。

`VariableDescriptor` 至少描述所属函数或控制点、存储类别、类型键、作用域和格式化键。局部变量事件必须结合 `CallInstanceId`，成员变量必须结合对象指针或对象实例。

`TypeDescriptor` 可以包含可选 TypeCode、大小、对齐、布局指纹、字段表和 serializer 键。没有 TypeCode 的类型使用 Replay-local type key。

### 6.2 外部格式化文件

`.dmap` 是精确构建的不可变字典，至少绑定：

- 项目 ID、构建 ID、源码修订和所有参与构建文件的内容摘要；
- 目标三元组、ABI、编译器/链接器版本、优化、LTO 和相同代码折叠状态；
- 映像哈希、调试产物哈希、编译数据库摘要；
- 函数、控制点、变量、类型、内联链和源代码跨度。

仅有 Git 提交号不足以确认映射正确。格式化程序发现构建或源文件摘要不匹配时必须拒绝静默还原。

## 7. 全局事件顺序和丢失语义

### 7.1 ID 分配

每个启用的运行时事件在记录尝试开始时执行一次：

```text
GlobalEventId = global_counter.fetch_add(1, relaxed)
```

ID 的线性化顺序是 Replay 认可的跨线程逻辑顺序。事件在取得 ID 后才申请块、复制快照和尝试入队；这些步骤失败不会回收 ID。

`GlobalEventId` 建议使用 `uint64_t`。计数器使用 `memory_order_relaxed`，信息块可见性由 MPSC 的 release/acquire 保证。32 位目标必须单独验证 64 位原子是否无锁；若不是无锁实现，Replay 的 Debug 性能和启用策略必须明确记录，不能假装与 x64 相同。

上一版讨论的 `(producer_id, producer_seq)` 不再是逻辑排序依据。`producer_id` 仍可作为诊断字段，但不能替代全局 ID。

### 7.2 物理顺序

生产者可能先取得 ID 后暂停，较大的 ID 可能先进入队列。因此消费者不得等待缺失的较小 ID。磁盘物理顺序只服务于追加和恢复；离线解析器负责按照 ID 进行外部归并。

### 7.3 缺口和尾部

相邻已见 ID 的差值表示中间至少丢失的事件数。正常 `unload()` 写结束水位：

```text
last_issued_event_id
last_persisted_event_id
clean_shutdown
```

没有结束水位的文件只能确认最后一个完整记录，尾部视为未知。对象生命周期或控制流跨过缺口时，解析器必须传播“不完整”状态，不能把两侧数据拼成确定事实。

## 8. ReplayInfoBlock 和固定块池

### 8.1 信息块形状

内存信息块分为传输头和语义载荷：

```text
TransportHeader
  pool_class
  producer_state_pointer
  GlobalEventId

EventHeader
  record_kind
  flags
  descriptor_pointer
  payload_size

Payload
  已复制的事件专属字节
```

磁盘记录不必与内存布局相同。消费者可以把内部生产者状态转换为稳定的 `ExecutionContextId` 后再写盘。

### 8.2 所有权状态

```text
free
  -> producer_owned
  -> queued
  -> consumer_owned
  -> free
```

入队成功后生产者不再读取或释放信息块；入队失败时生产者归还块。消费者写完后归还块。块池的空闲结构必须处理多生产者申请、生产者失败归还和消费者归还的并发 ABA 问题。

### 8.3 容量和缓存

v1 建议使用编译期确定的多个块类别：small、medium、large。生命周期和控制事件应有独立的小块配额，避免大值快照耗尽所有资源。

不采用线程本地页，也不保证把某个变量推出或保留在 L3。缓存行为通过固定池大小、队列控制字段对齐和实测基准决定。块容量、类别数量和预留比例在基准测试后冻结，不能凭空写入性能数字。

v1 不使用链式块。超过最大类别的值快照整体丢弃并留下 ID 缺口，不写未经标记的部分数据。

## 9. 运行时事件模型

### 9.1 函数事件

`FunctionEnter` 保存函数描述符、调用实例 ID、父调用实例和可选调用点。进入事件的 `GlobalEventId` 可作为 `CallInstanceId`。

`FunctionExit` 保存调用实例和可选返回快照。没有 C++ 异常时仍应保留正常返回、错误返回和取消/提前离开原因；如果函数异常离开或记录丢失，解析器必须把调用帧标记为不完整。

### 9.2 控制流事件

`ControlDecision` 保存控制点描述符、选中的边和短路求值掩码：

```text
if/while/for       true 或 false 边
switch             case/default 边
&& / ||            实际求值操作数掩码
break/continue     转移边
return             退出边和原因
```

`if constexpr` 和预处理器 `#if` 不产生运行时事件，因为它们不是运行时控制流。

Replay 核心不重复求值表达式。插桩层必须保证表达式只执行一次，再把已经得到的结果和求值掩码提交给 Replay。

### 9.3 对象生命周期

所有对象统一使用构造和析构事件。构造成功后记录对象指针和类型描述符；析构记录对象指针和结束原因。地址复用由解析器内部的生命周期代数区分。

在正常结束、相关 ID 区间完整且对象仍有构造而无析构记录时，解析器判定泄漏。若区间有缺口、进程崩溃或模块没有提供完整生命周期观测，只能判定为未知。

### 9.4 变量和值快照

值快照包括：变量描述符、绑定引用、值角色、编码方式、长度和已经复制的字节。

默认支持：

- 标量位模式；
- 指针数值和指针类别；
- 有界字节快照；
- 外部 blob 引用；
- `unavailable`、`redacted`、`sha256` 等明确状态。

Replay 不盲目复制非平凡 C++ 对象，不自动解引用指针，不保存临时字符串或业务对象引用。结构化对象必须由模块提供 serializer 或由 `.dmap` 提供字段布局。

写入前和写入后可以是两条独立事件；模块不需要为每个操作都付出双份快照成本。

### 9.5 基础类型策略

Replay 不自动记录每个基础数值加减乘除。只有以下情况才建议记录：

- 类型不变量或边界状态发生变化；
- 容易出现所有权、长度、索引或生命周期错误的操作；
- 错误路径、状态转换和资源申请/释放；
- 模块开发者明确标记的参数、返回值和条件操作数。

## 10. 文件分工和恢复

### 10.1 `.dtrace`

运行期文件包含：

```text
固定 magic 和 Replay 文件 TypeCode
运行实例头
静态描述符前导区
运行时事件记录
可选 checkpoint / loss 信息
结束记录
```

所有整数采用小端序，记录具有明确长度。内部 Replay `record_kind` 可以作为局部结构标签；文件自身和需要进入 Destiny 全局身份空间的语义项继续使用 TypeCode。

v1 不要求独立索引文件。解析器可以扫描事件并建立自己的 `GlobalEventId -> file offset` 索引。未来若增加 `replay.index`，必须使用独立文件 TypeCode，且不能改变主事件文件的语义。

### 10.2 `.dmap`

`.dmap` 是构建期生成的静态映射文件，保存模块、函数、控制点、变量、类型、源码跨度、内联链、ABI 和源文件摘要。它不包含某次运行的对象实例和事件顺序。

运行时原始指针通过模块实例、加载基址、相对地址或描述符指针连接到 `.dmap`。如果映射不唯一或构建不匹配，结果必须显式标记 `ambiguous` 或 `unavailable`。

### 10.3 恢复规则

- 文件头身份不匹配时拒绝读取；
- 尾部不完整记录只截断最后损坏部分；
- 中间 ID 缺口保留为丢失证据；
- 未知可选记录按长度跳过；
- 未知必需特性直接失败；
- 没有 clean shutdown 时，不对文件尾部对象和调用帧做确定结论。

## 11. 解析器职责

离线解析器按以下顺序工作：

```text
验证文件头和记录长度
    ↓
验证 build_id / source hash / image identity
    ↓
按 GlobalEventId 归并事件
    ↓
按 ExecutionContextId 维护调用栈
    ↓
解析控制点边和短路掩码
    ↓
维护对象构造/析构表
    ↓
解释变量和类型快照
    ↓
传播丢失、不完整和歧义状态
    ↓
生成时间线、泄漏报告和源代码视图
```

JSON、火焰图、源码标注和 UI 查询都是派生视图，不是 Replay 权威格式。

## 12. 实施计划

### 阶段 0：协议和命名冻结

交付物：

- 本计划文档和术语表；
- Replay 文件 TypeCode 的分配方案；
- `GlobalEventId`、`ExecutionContextId`、`CallInstanceId` 的语义；
- `record_kind`、描述符类别和事件字段的编号表；
- Debug/Release 宏和 CMake 传播规则。

验收：不存在“每线程序号作为主顺序”“运行时开关”“Replay-local identity 必须 TypeCode”等旧方案残留。

### 阶段 1：编译模式和模块骨架

交付物：

- `define` 模块提供构建模式宏；
- Replay 的最小 public header 和 `onload/unload` 契约；
- Release 空操作路径；
- Debug enabled/disabled 的 target 定义。

验收：Release 编译单元不求值 Replay 参数、不链接运行时采集实现；Debug 两种开关均能通过编译和基础测试。

### 阶段 2：块池和 MPSC 适配

交付物：

- 固定块类别和所有权状态机；
- 指针型有界 MPSC 适配；
- 多生产者申请、失败归还、消费者归还的并发测试；
- ABA、池耗尽和队列满的行为定义。

验收：无动态分配热路径；失败不阻塞业务；压力测试能正确回收所有块；队列实现本身不调用 Replay。

### 阶段 3：全局 ID、执行上下文和元数据封存

交付物：

- 64 位全局原子 ID；
- 执行上下文实例分配和 Replay-owned producer state；
- 模块/函数/控制点/变量/类型描述符注册；
- `sealMetadata` 屏障和模块生命周期检查。

验收：并发下 ID 不重复；池/队列失败留下可验证缺口；模块卸载后 Replay 不访问悬空描述符；静态元数据能在事件前完整读取。

### 阶段 4：事件编码和运行期 writer

交付物：

- 公共事件头和四类核心事件；
- 快照复制、指针编码、长度和状态标志；
- `.dtrace` 文件头、前导区、事件记录和结束水位；
- 尾部恢复、缺口识别和 clean shutdown。

验收：事件物理乱序不影响按 ID 解析；截断只丢最后不完整记录；未知可选记录可跳过；磁盘失败不反向影响业务。

### 阶段 5：构建映射契约和 `.dmap` 生成器接缝

交付物：

- 精确 build manifest；
- 函数、控制点、变量和类型表；
- ASLR/RVA 和 descriptor pointer 的连接规则；
- 源文件内容摘要和映射质量字段。

验收：错误构建或源文件摘要被拒绝；内联、模板、代码折叠和歧义位置不会静默映射到错误源码。

### 阶段 6：模块侧插桩适配器

交付物：

- 函数进入/退出适配器；
- 控制点和短路掩码适配器；
- 对象构造/析构适配器；
- 变量和值快照适配器。

先在一个需要诊断的非基础数值操作上验证，不把 `destinyNumeric` 的全部基础运算自动插入 Replay。

验收：表达式只求值一次；快照不保存借用引用；异常/早退/地址复用状态可解析；模块可以逐点选择采集。

### 阶段 7：离线解析器最小闭环

交付物：

- `.dtrace` 验证和按 ID 归并；
- `.dmap` 精确匹配和地址解析；
- 调用栈、控制流、对象生命周期和变量快照重构；
- 丢失区间传播和泄漏候选/确定结论区分。

验收：构造无析构、短路分支、循环、递归、地址复用和并发事件均有可重复的解析结果。

### 阶段 8：性能、平台和协议冻结

交付物：

- GCC/Clang、x86/x64 的 Debug/Release 矩阵；
- 全局 64 位原子能力和成本报告；
- MPSC、块池、ID 计数器和 writer 基准；
- 长时间运行、磁盘尾部损坏和大文件恢复测试；
- v1 字段/编号/特性冻结和发布说明。

验收：用真实模块工作负载测量 Replay 额外成本，不使用未经测量的“每秒事件数”或缓存占用承诺。

## 13. 验收测试清单

- Release 下 Replay 宏不求值参数且不产生运行时符号依赖；
- Debug disabled 和 enabled 均通过编译、启动和卸载测试；
- 多生产者并发取得的全局 ID 唯一且可排序；
- 池耗尽、队列满、块归还和 writer 乱序不会发生双重释放；
- ID 缺口数量与故意丢弃数量一致；
- 模块 onload 注册、seal、unload 顺序正确；
- 函数递归、早退、控制点、短路、循环和 switch 可重构；
- 对象地址复用不会复用解析器生命周期身份；
- 没有丢失的构造而缺失析构可判定泄漏；跨缺口对象被标记未知；
- 标量、指针、blob、不可用、脱敏和超大快照状态可区分；
- 文件尾截断、未知可选记录、格式不匹配和错误构建均有明确结果；
- x86/x64、GCC/Clang 和 Debug/Release 的 ABI/原子差异有记录；
- 真实工作负载下确认全局原子、块池和 writer 的开销；
- Replay 内部失败不会抛出异常或改变业务返回结果。

## 14. 实现前仍需冻结的项目

下列项目尚未授权凭空确定数值，必须在实现阶段通过基准或明确决策冻结：

1. 最终宏名和 CMake option 名；
2. 32 位目标上 64 位原子非无锁时的启用策略；
3. small/medium/large 块容量、池总量和生命周期预留比例；
4. `ExecutionContextId` 从 thread 固定槽位还是平台线程适配器取得；
5. 静态描述符由手写注册表、宏、编译器插桩还是生成代码产生；
6. `.dmap` 的精确构建键和源代码跨度编码；
7. 聚合类型 serializer 是否进入 v1，及其 ABI/版本契约；
8. 是否在 v1 写入时间戳、同步事件和可选 blob；
9. Replay 主文件和 `.dmap` 的具体 TypeCode 数值；
10. 是否需要独立索引文件，以及索引损坏后的重建策略。

这些项目不改变已经冻结的基本方向。任何实现若需要改变全局 ID、MPSC 指针所有权、编译期开关、TypeCode 兼容性或对象生命周期语义，必须先修改本计划并重新评审。

## 15. 设计结论

Replay 的核心不是把所有值都写入磁盘，而是建立一条低干扰、可检测丢失、可由外部映射还原的事实流：

```text
编译期描述符
    + 运行期原始指针和快照
    + 全局原子事件 ID
    + 有界 MPSC 指针队列
    + 明确的生命周期和控制流事件
    + 精确构建映射文件
    = 可验证的细粒度诊断追踪
```

本计划只授权后续进入接口、块池、文件 writer、插桩适配器和离线解析器的分阶段设计；不授权在未冻结的字段和容量上直接实现业务逻辑。
